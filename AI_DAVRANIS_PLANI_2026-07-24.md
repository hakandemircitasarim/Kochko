HEADLINE: KOCHKO records everything, spends almost none of it, and never checks whether anything it said worked — 18 fixes that turn a state-describer into a coach

VERDICT: Behaviorally this is a 5/10 coach wearing a 9/10 instrumentation harness. The plumbing is genuinely excellent — a 4-layer context, a canonical safety spine, ~15 deterministic extraction nets, a bitemporal belief log, portion calibration, learned meal times, a relationship ladder, a glass-box memory mirror. Almost none of it changes what the coach SAYS. The core deficiency is loop closure: it never leaves the user with one small next action, never checks whether the action happened, never learns whether its own advice landed (ai_feedback has zero edge readers; user_commitments has only INSERTs; behavioral patterns carry an `intervention` with no outcome field; weekly_compliance has no writer at all, so the habit ladder can never advance past habit #1). Second deficiency: the reply is defined by prohibition — 66 ASLA/YASAK across system-prompt.ts + task-modes.ts, one positive exemplar, no obligation to spend a single observation — so the model optimizes for not-violating and converges on bland. Third: the app's own code is the loudest robot tell — the conflict nets stack 3-5 questions into one reply while the prompt mandates one, and they emit the exact phrases ("Kaydettim:", 🙂, aksansız "Dogru anladiysam") the prompt bans. Fourth, and worst for trust: consent is inverted — it asks permission for a 200-kcal plate it already wrote, then silently rewrites the user's entire calorie band for three weeks behind a badge reading "Profil güncellendi" (and index.ts:1501-1509 even INJECTS maintenance_start when the model forgets it). The good news: ~11 of these 18 are prompt sections, one-line renderer changes, or context blocks assembled from data that is already fetched.
