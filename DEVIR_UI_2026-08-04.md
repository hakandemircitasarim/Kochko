```

Paket    : com.kochko.app  (debug APK kurulu)
Metro    : localhost:8081
```

### Debug APK derleme (gerekirse)
```bash
cd android && ./gradlew assembleDebug -PreactNativeArchitectures=x86_64
```
`-PreactNativeArchitectures=x86_64` **şart**: dört mimarili APK 231 MB ve emülatöre
sığmıyor. Tek mimariyle 85 MB, ~33 saniyede derleniyor.

### Derin bağlantı — gezinmenin en güvenilir yolu
Dokunma koordinatlarıyla uğraşmak yerine doğrudan rotaya git:
```bash
export MSYS_NO_PATHCONV=1
ADB="$LOCALAPPDATA/Android/Sdk/platform-tools/adb.exe"
"$ADB" shell am start -a android.intent.action.VIEW -d "kochko://settings/goals" com.kochko.app
```
Şema `kochko`. `kochko://log`, `kochko://plan/diet`, `kochko://plan/workout`,
`kochko://settings/<sayfa>` çalışıyor.

**Uyarı:** derin bağlantı, o rota zaten monteliyse **iç state'i sıfırlamaz**
(`log.tsx` barkod ekranındayken `kochko://log` seni barkodda bırakır). Önce X'e bas.

**Giriş ekranları oturum kapatmadan açılıyor:** `kochko://login`, `kochko://register`,
`kochko://reset-password`, `kochko://onboarding` oturum açıkken de çiziliyor. Çıkış
yapıp oturumu yeniden enjekte etmene gerek yok.

**Geliştirici "Tools" düğmesi başlığın sağ üstünü kapatıyor** — `Çık`/`İptal` gibi
header düğmelerine dokunamıyorsun, dokunuşu dev menüsü yutuyor. Çözüm: düğmeyi
sürükleyip aşağı taşı (`input swipe 1010 124 300 1700 900`) ya da dev menüsündeki
"Tools button" anahtarını kapat.

### Dokunma koordinatı — tahmin etme, oku
Kaydırma momentumu yüzünden ekran görüntüsünden ölçülen koordinatlar sık ıskalıyor.
Düğümün gerçek sınırlarını al:
```bash
"$ADB" shell rm -f /sdcard/u.xml
"$ADB" shell uiautomator dump /sdcard/u.xml
"$ADB" exec-out cat /sdcard/u.xml | tr '<' '\n' | grep -o 'content-desc="1 bardak su ekle"[^>]*bounds="[^"]*"'
```
`rm -f` **şart** — dump başarısız olursa `cat` eski dosyayı okur ve yanlış teşhis koyarsın
(bir kez modalın açık olduğunu sandım, ekran hâlâ önceki sayfadaydı).

## 4. GİRİŞ EKRANINA DÜŞTÜ — ÖNCE ÖLÇ

İkinci oturumda bu **iki kez** oldu ve **her ikisinde de oturum geçerliydi** (biri hatta
kendini tazelemişti, `expires_at` ilerlemişti). Sebep oturum değil, Fast Refresh'in tam
yeniden yükleme yapması ve uygulama durumunun takılmasıydı.

| # | Sebep | Nasıl ayırt edilir |
|---|---|---|
| 1 | Enjekte oturum doldu | Cihazdan oku, `expires_at` bak. |
| 2 | **Tam yeniden yükleme, hidrasyon yetişmedi** (en sık) | ~20 sn bekle; düzelmezse `force-stop` + yeniden başlat, ~10 sn'de gelir. |
| 3 | Dev-launcher yüklenmemiş | `uiautomator dump` → "DEVELOPMENT SERVERS" görüyorsan sunucuya dokun. |
| 4 | Metro soğuk derleme | `node` süreci CPU yakıyorsa çalışıyordur. |

**Fast Refresh ne zaman tam yeniden yükleme yapar:** dosyaya yeni bir üst-seviye bileşen
veya yeni bir `import` eklediğinde. Sadece stil/JSX değiştirdiğinde state korunur — bu
çok işe yarıyor: **modal açıkken düzenle, yerinde güncellensin** (karşılaştırma modalını
ve CTA hizalamasını böyle doğruladım, tekrar LLM çağrısı harcamadan).

**Metro'nun paket ürettiğini kanıtlama komutu:**
```bash
curl -s -o /dev/null -w "%{http_code}" --max-time 560 \
  "http://localhost:8081/node_modules/expo-router/entry.bundle?platform=android&dev=true&transform.routerRoot=app"
```
`200` bekle. `/index.bundle` **yanlış yoldur** (Expo Router'da 404).

- **Kamera üstündeki metin gölge ister.** `log.tsx`'te `ON_CAMERA_TEXT` var, kullan.
- **Başlıklar cümle düzeni.** ("Barkod Tara" → "Barkod tara", "Tartı Kaydı" → "Tartı kaydı".

- **`textTransform:'uppercase'` Türkçe'de BOZUKTUR** (i→I). `toLocaleUpperCase('tr-TR')`
  kullan. Uygulama geneli süpürüldü (7 yer); ekranda **"DIĞER", "ALERJI", "AMELIYAT",
  "PORSIYON", "E-POSTA DEĞIŞTIR"** yazıyordu. Şu an canlı hiçbir yerde kalmadı —
  yenisini eklersen aynı hatayı geri getirirsin.
- **Yayılımdan SONRA elle `lineHeight` yazma.** `{ ...TYPE.body, lineHeight: 20 }` token'ın
  22'sini ezer; token'a bağladığını sanarsın ama satır aralığı eski sıkışık hâlinde kalır.
  26 yerde vardı, temizlendi. Tarama: `grep -rn "\.\.\.TYPE\.[a-zA-Z]*,[^}]*lineHeight"`
- **Paylaşılan bileşeni büyütmek uzak ekranlarda kırpar.** `Input` 13→15'e çıkarıldığında
  `chat-history`'nin yarım genişlikteki tarih alanı ikinci satıra sarıp kırpıldı — ve bu

  değiştirdiğinde, onu **dar kaplarda** kullanan yerleri ayrıca tara:
  uzun `placeholder` + `flex: 1` + `flexDirection: 'row'`.

## 7. ÖLÇEK İŞİ BİTTİ — kalan ham `fontSize` yok

**Üçüncü oturumda kapandı.** 491 → 244 → **0**. Canlı hiçbir yüzeyde ham `fontSize`
kalmadı. Bugün bağlananlar: plan akışı (11 dosya), profil + dashboard (10), giriş /
kayıt / onboarding / şifre sıfırlama (5), kuyruk (18).

Kodda hâlâ görünen 44 sayı **kasıtlı**, dokunma:

```
28  app/settings/premium.tsx   ölü yüzey (FREE_LAUNCH altında gizli)
11  src/lib/design.ts          ölçeğin kendi token tanımları
 3  weekly-menu / recipes / household   işaret glifi: +  ★  ✓

```

Tarama: `grep -rn "fontSize:" app src --include=*.tsx | grep -v "TYPE\."`

**Sonraki cephe adayı — DERİNLİK (ölçüldü, henüz uygulanmadı).** `design.ts` dört ayak
vadediyor: TYPE ✔, SPACE ✔ (constants.ts'teki SPACING/RADIUS zaten aynı merdivene
göre yeniden ayarlanmış), MOTION ✘, **DEPTH ✘**. `elevation()`, `surface()`, `RADII`,
`SPACE`, `MOTION` şu an **sıfır** dosyada kullanılıyor.

Üçüncü oturumda `Card` primitifine `elevation(1)` verip cihazda ölçtüm: **karanlık
temada görünür hiçbir fark yok** ve değişiklik geri alındı. Sebep `design.ts`'in kendi
notunda yazılı: koyu yüzeyde kaldırma gölgeden değil, **daha açık arka plandan** gelir
(`card #1A1A24` → `cardElevated #22222E`). Android zaten yalnız `elevation` sayısını
okur, siyah üstünde siyah gölge görünmez. Yani derinlik istiyorsan yol gölge değil,
**yüzey tonu basamağı** — ve bu her kartın rengini değiştiren bir tasarım kararı, senin
gözünle onaylanmalı. Açık temada gölge gerçekten çiziliyor, orası ayrıca ölçülmeli.

> **Bu ölçümün asıl dersi:** ilk üç denemede de "fark yok" çıktı ve neredeyse
> "elevation Android'de işe yaramıyor" diye not düşüyordum. Kırmızı 4px kenarlıkla
> **aleti sınadım**: o da görünmüyordu. Emülatörün ağını kapatıp açtığımda Metro
> soketi düşmüş, Fast Refresh o andan beri hiçbir şeyi iletmiyormuş. **Ekran
> görüntüsü "değişmedi" diyorsa, önce değişikliğin ekrana ULAŞTIĞINI kanıtla.**
> Görünür bir işaret (kalın kırmızı kenarlık) 30 saniye sürüyor ve yanlış bir
> teşhisi kayda geçmeni engelliyor.

**Verimli döngü (ikinci oturumda ~50 dosya böyle bitti):**
1. Grubun "öncesi" ekran görüntülerini toplu al (derin bağlantı + `screencap`, ~7 sn/sayfa).
2. Kalıp eşlemeli script ile hepsini birden token'a bağla (aşağıdaki harita).
3. `npm run lint` + `npm run arch-guards`.
4. Tek yeniden başlatma, sonra "sonrası" görüntülerini toplu al, 3'lü kontak sayfası hâlinde bak.

Kalıp haritası (en özelden genele; sıra önemli):
```
FONT.xl|lg + w600-800  -> TYPE.title3      FONT.sm + w500-600 -> TYPE.bodyStrong
FONT.md   + w500-800   -> TYPE.headline    FONT.sm            -> TYPE.body
FONT.md                -> TYPE.body        FONT.xs + w700     -> TYPE.caption/w700
FONT.sm   + w700-800   -> TYPE.bodyStrong/w700                -> ALL-CAPS ise TYPE.overline
                                           FONT.xs            -> TYPE.caption
```

**Script yazarken dört tuzak:**
- `...TYPE.x` yayılımı kendinden ÖNCE gelen `fontWeight`'i ezer.
  Tara: `grep -n "fontWeight:[^,]*,[^}]*\.\.\.TYPE" <dosya>`
- Yayılımdan SONRA kalan `lineHeight` token'ı ezer (§5'teki kural).
- 11'in altındaki ham sayılar (9/10) kalıba uymaz — kabın genişliğini **önce oku**, sonra
  karar ver: geniş yerde `caption`(13), dar ızgara/kutucuk/baloncuk içinde `footnote`(11).
- JSX yorumu (`{/* */}`) yalnız JSX çocuk konumunda geçerli; ternary'nin içine koyarsan
  derleme kırılır. İfade bağlamında `//` kullan.

**Bash heredoc uyarısı:** uzun/çok satırlı Python script'lerini `<<'PY'` ile geçirme —
bu oturumda bir kez satır ortasından bölündü. Script'i dosyaya yazıp `python dosya.py`
ile çalıştır.
